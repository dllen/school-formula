Approach Comparison

Three approaches for the prompt template feature

Approach A: 嵌入式增强 (Embedded Enhancement)

Add prompt template selector directly into the existing KnowledgeDetail AI panel. Users see a "模板模式" toggle alongside the existing simple AI mode.

Pros

  • Minimal new code — extends existing AI panel
  • Users discover templates in context (already looking at a knowledge point)
  • Can auto-fill knowledge point context into templates
  • Consistent with "AI 助教子功能" choice

Cons

  • Limited screen space in the detail page
  • Hard to browse all templates (only sees ones linked to current KP)
  • Less discoverability for the full template library

Approach B: 独立视图 + 嵌入式入口 (Hybrid)

Add a "提示词中心" accessible from Header or Home, PLUS embed template shortcuts in the KnowledgeDetail AI panel. Best of both worlds.

Pros

  • Full browsing experience in a dedicated view
  • Contextual access from knowledge points
  • Users can discover templates they wouldn't find otherwise
  • Scales well as template library grows
  • More code — new view component + routing
  • Need to decide: new tab or sub-route
  • Slightly more complex navigation

Approach C: 全屏模态框 (Modal Overlay)

Prompt template selector opens as a full-screen modal from the KnowledgeDetail page. No new navigation needed — everything happens within the AI interaction flow.

Pros

  • Zero navigation changes
  • Rich browsing experience within modal
  • Context-preserving — user never leaves the knowledge point
  • Fastest to implement
  • Modal can feel cramped for browsing 50+ templates
  • Not discoverable from other parts of the app
  • Harder to link to from other features
